# 結（yui）

[![テスト](https://github.com/kentakusu/yui/actions/workflows/ci.yml/badge.svg)](https://github.com/kentakusu/yui/actions/workflows/ci.yml)

日本語でそのまま問い合わせる、小さな組み込みグラフ DB です。C99 で書いてあり、外部のライブラリは使いません。

```
yui> 結ぶ (案件:結の開発)-[担当]->(人:田中)
(案件:結の開発)-[担当]->(人:田中)
作りました

yui> 辿る (人:田中)<-[担当]-(?案件)
(人:田中)<-[担当]-(案件:結の開発)
1 件
```

## これは何か

作者が自分の知識置き場に使うためのものです。**堅牢さも商用利用も考えていません。**

- **全部 日本語** — README・コメント・エラーメッセージ・問い合わせの言葉まで。国際化はしません
- **組み込みと単体の両方** — SQLite のように、ライブラリとしても CLI としても使えます
- **1 ファイルに保存** — `*.yui` を 1 つ持ち歩くだけです
- **辞書なしの日本語検索** — 文字の 2〜3-gram で部分一致します

**他の方が使われるなら「緩い前提」でお願いします。** 壊れても直す約束はしていません。

### 組み込むとき

`yui.c` と `yui.h`（Windows なら `yui_win.h` も）を自分のプロジェクトに入れて、一緒にコンパイルするだけです。`yui_cli.c` は CLI 用なので要りません。

```c
yui *db;
if (yui_open("知識.yui", &db) != YUI_OK) {
    fprintf(stderr, "%s\n", yui_errmsg(db));
}
yui_exec(db, "結ぶ (案件:結の開発)-[担当]->(人:田中)", 行ごとの関数, 文脈);
yui_close(db);
```

関数名だけは ASCII です（Swift や JNI から呼びやすいように）。

★**機械で読む形が要るなら `yui_exec_json` を使ってください。**`yui_exec` と同じですが、1 行を 1 つの JSON で返します（[機械で読む形](#機械で読む形--json)）。行の数と順は同じです。

★**`query` に NUL（文字コード 0）を入れないでください。** C の文字列として受け取るので、NUL があるとそこが終わりになり、そこから先は渡りません。文字列の途中に NUL があると「文字列が閉じていません」という、理由の分からないエラーになります。**バイト数で読んでいる側にしか分からないので、渡す前に数えてください**（`yui_cli.c` が実際にそうしています）。

★**wasm（emscripten）から呼ぶときは、長い問い合わせを `cwrap` の `'string'` 引数で渡さないでください。** スタックに積まれるので、**数千の文を 1 回で渡すと `memory access out of bounds` になります**。`_malloc` で確保して、ポインタを渡してください。

★**`yui_cb` が 0 以外を返すと、`yui_exec` に渡した残りの文が全部 実行されません。** 「返す行を N 件までにする」つもりで途中で止めると、後ろにある書き込みの文が黙って落ちます（戻り値は `YUI_OK` のままです）。数を絞りたいだけなら、0 を返し続けて受け取る側で捨ててください。

## 使い方

```
yui 知識.yui              対話で使う
yui 知識.yui "探す 田中"    1 回だけ実行する
yui --json 知識.yui …      1 行を 1 つの JSON で出す（機械で読むとき）
```

標準入力から流し込むこともできます。**誤りの行があっても止まらず、次の行へ進みます**（300 行 流して 1 行 間違っていたときに、残りを全部 捨てるほうが困るので）。失敗した行は `エラー: 2 行目: …` の形で標準エラーに出て、終了コードは 1 になります。

```sh
yui 知識.yui < 命令.txt
```

### 機械で読む形（`--json`）

`--json` を付けると、**1 行に 1 つの JSON**（JSON Lines）で出ます。行の数と順は人が読む形と同じです。

```sh
$ yui --json 知識.yui '一覧 (発言:) 見せる 日時,話者'
{"kind":"node","label":"発言","name":"x1","attrs":{"日時":"07:30","話者":"本人"}}
{"kind":"node","label":"発言","name":"x2","attrs":{"日時":"08:00","話者":"相手"}}
{"kind":"summary","text":"2 件","count":2}
```

**鍵は ASCII です。値（ラベル・名前・属性）は日本語のまま**入ります。関数名を ASCII にしているのと同じ理由で、読むのが機械だからです。

| `kind` | 中身 |
|---|---|
| `node` | `{"label":…,"name":…,"attrs":{…}}` |
| `edge` | `{"type":…,"from":{…},"to":{…},"attrs":{…}}` |
| `path` | `{"nodes":[…],"edges":[{"type":…,"forward":真偽,"attrs":{…}}]}`（`辿る` の道。`nodes` は `edges` より 1 つ多い） |
| `link` | `{"dir":"out"\|"in","type":…,"attrs":{…},"other":{…}}`（`見る` のつながり） |
| `text` | `{"text":…}`（`手引き` など、人へのそのままの 1 行） |
| `summary` | `{"text":…}`。件数が分かるときは `"count"` も入る |

- **文字列は JSON として逃がされます。** 本文に改行や引用符が入っていても、読む側で戻す必要はありません
- **数は数のまま**出ます（`"順":1`・`"重み":0.5`）。引用符は付きません
- 失敗は標準エラーに `{"kind":"error","line":2,"text":…}` の形で出ます（流し込みのときは `line` 付き）
- `名前だけ` や `見せる` はそのまま効きます（`attrs` が絞られます）

★**`jq` で日本語の属性名を引くときは `["…"]` で囲んでください。** 点のあとに続ける書き方は**構文エラーになります**（jq 1.7 で確認）。

```sh
jq -r '.attrs.本文'      # → jq: error: syntax error …
jq -r '.attrs["本文"]'   # → あいう
```

鍵が ASCII のところ（`kind`・`label`・`name`・`attrs`・`count`）は点で続けられます。

```sh
# 書いたあとに件数を数え直す
yui --json 知識.yui '一覧 (発言:) 名前だけ' \
  | jq -s 'map(select(.kind=="summary"))[0].count'
```

標準入力が端末でなければ、1 行ずつ実行します。

```
yui 知識.yui < 命令.txt
```

## 言葉

1 行が 1 文です。行末の `。` はあってもなくても構いません。`#` から行末はコメントです。

| 言葉 | すること | 例 |
|---|---|---|
| `作る` | 点を作る | `作る (人:田中 {役職: "部長", 年齢: 42})` |
| `結ぶ` | 線を結ぶ（点が無ければ作る） | `結ぶ (案件:結の開発)-[担当 {開始: "2026-11"}]->(人:田中)` |
| `探す` | 文字列の部分一致 | `探す "既読"` / `探す "既読" (メモ:)` |
| `辿る` | つながりを辿る | `辿る (人:田中)<-[担当]-(?案件)` |
| `見る` | 属性とつながりの一覧 | `見る (人:田中)` |
| `一覧` | そのラベルの点すべて | `一覧 (人:)` |
| `消す` | 点や線を消す | `消す (人:田中)` |
| `詰め直す` | 取り消した記録をファイルから落とす | `詰め直す` |
| `同期` | ここまでを書き出す | `同期` |
| `手引き` | 使い方を出す | `手引き` |
| `終わる` | 終わる | `終わる` |

★`探す`・`辿る`・`一覧` の末尾には**修飾**を書けます（[新しい順に N 件](#新しい順に-n-件)・[名前だけ](#名前だけ)・[見せる](#見せる-ab)。[まとめ](#修飾のまとめ)）。

★`見る` の締めの「N 件」は**点の数**です。つながりの行がいくつ出ても、1 つの点を見たなら `1 件` になります。

★`探す` が探すのは**書かれている文字そのもの**です。**漢字の読みでは当たりません** — `探す "かいぎょう"` で `改行` は見つかりません。かな・英数字の揺れはそろえます（[日本語の検索](#日本語の検索)）。

#### `探す` が見ている範囲

| | |
|---|---|
| 当たる | 点の名前・**点の属性の値**・**線の属性の値** |
| 当たらない | 点のラベル・線の種類 |

**線も返ります。** `探す "さくら"` は、本文に「さくら」が入った点と、`-[宛て {理由: "さくら"}]->` のような線の両方を返し、どちらも 1 件に数えます。

**点だけが欲しいときは、点の形を書きます。**

```
探す "さくら"          # 点も線も
探す "さくら" (便:)     # (便:…) の点だけ。線は返りません
```

★**ラベルは探しません。** `(上げる:…)` という点が在っても `探す "上げる"` は 0 件です。代わりに、**0 件のときだけ締めの行で知らせます**。

```
> 探す "上げる"
0 件（「上げる」は点の種類です。一覧 (上げる:) で引けます）
```

ラベルを探す対象に入れれば当たるようになりますが、同じラベルの点が何万と並ぶ使い方では索引がその分だけ太るので、**メモリを増やさずに迷いを解く**ほうを選びました。

### 括弧の読み方

ここを書き分けるのが、この言葉の肝です。

| 書き方 | 意味 |
|---|---|
| `(田中)` | その名前の点（ラベルは問わない） |
| `(人:田中)` | 種類つきの点 |
| `(人:)` | その種類のどれでも |
| `(?相手)` | 誰でも。結果を受け取る変数になる |
| `()` | 何でも |

線の向きは `->`・`<-`・`-`（両方）です。段数を足すと多段で辿ります。

```
辿る (私)-[返信 3段]->(?相手)     # 3 段先まで
辿る (私)-[]->()                 # 種類も相手も問わない
```

### 新しい順に N 件

`探す`・`辿る`・`一覧` の末尾に `新しい N` と書くと、**新しい順に N 件**だけ返します。付けなければ今までどおり、古い順に全件です。

```
一覧 (便:) 新しい 20
辿る (人:田中)<-[宛て]-(?便) 新しい 20
探す "見積" (便:) 新しい 20
```

★**「新しい」は時刻を見ません。点の id の大きい順です。** 結は追記しかせず、id は書いた順に振られるので、**id が大きい＝後に書いた**が常に成り立ちます（`詰め直す` で振り直しても、生きている点を順に書くので順序は保たれます）。**属性に書いた `時刻` では並びません。**

★**返す数であって、見る数ではありません。** `辿る` は全部 歩いてから N 件 返します。先に打ち切ると、あとで見つかるはずの新しい点を落とすためです。

★**入口が 2 つ以上あるときは気をつけてください。** 2 つの流し込みを順に書くと（先に A を全部、次に B を全部）、**id の順と時刻の順がずれます**。新しい順に出したいなら、**書く前に時刻の順に並べてから流してください**。

★**`探す` に付けるときは、点の形も書いてください。** 絞らない `探す` は線も返しますが、点の id と線の id は別の数直線なので、混ざったものを新しい順に並べられません。

```
探す "見積" 新しい 20          # エラー。並べられません
探す "見積" (便:) 新しい 20     # これなら並びます
```

`見る` には付きません（1 つの点を見る言葉なので）。

### 名前だけ

末尾に `名前だけ` と書くと、**属性を出さず、ラベルと名前だけ**返します。`新しい N` と一緒にも書けます（順序は問いません）。

```
一覧 (メモ:) 名前だけ
探す "見積" (便:) 新しい 20 名前だけ
辿る (人:田中)<-[宛て]-(?便) 名前だけ
```

**本文を属性に入れていると、1 件で何百 KB にもなります。** 結果を見て「どれを開くか」決めるだけなら、名前だけで足ります。使う側が文字列を切り分けて名前を取り出す必要もなくなります。

★**点の属性も線の属性も消えます。** `辿る` は線の属性を出す言葉なので、そこでも効きます。

`見る` には付きません（属性とつながりを見る言葉なので）。

### 見せる a,b

末尾に `見せる` と属性の名前を並べると、**その属性だけ、並べた順に**出します。

```
一覧 (発言:) 見せる 日時,話者
探す "見積" (便:) 新しい 20 見せる 日時
辿る (日:2026-11-08)-[含む]->(?発言) 見せる 順
```

**名前に意味が無いとき**（取り込み元が振った id など）は、`名前だけ` ではどれが何か分かりません。属性を 1〜2 個 添えれば、1 件ずつ `見る` を打たずに済みます。

- **並べた順に出ます**（点が持っている順ではありません）
- **持っていない属性は黙って飛ばします。** 点ごとに持ち物が違うのが普通なので、エラーにはしません
- 並べられるのは **16 個**までです
- `名前だけ` と一緒には書けません（どちらも属性の出し方を決めるので）

★**`辿る` では、辿り着いた点の属性にも効きます。**

```
辿る (日:2026-11-08)-[含む]->(?発言)
  (日:2026-11-08)-[含む {順: 1}]->(発言:x1)

辿る (日:2026-11-08)-[含む]->(?発言) 見せる 日時,話者
  (日:2026-11-08)-[含む]->(発言:x1 {日時: "07:30", 話者: "本人"})
```

`辿る` は**既定では点の属性を出しません**（道が主役の行なので、全部 並べると形が読めなくなります）。`見せる` で名前を挙げたときだけ、その属性が点にも出ます。線と点の属性を一緒に挙げてもかまいません（`見せる 日時,順`）。

### 修飾のまとめ

| 修飾 | すること |
|---|---|
| `新しい N` | 新しい順に N 件だけ返す |
| `名前だけ` | 属性を出さない |
| `見せる a,b` | その属性だけ、並べた順に出す |

`探す`・`辿る`・`一覧` に付けられます。**順序は問いません**し、`新しい N` は `名前だけ` / `見せる` と組み合わせられます。同じ修飾を 2 回 書くとエラーです（打ち間違いが「効かなかった」の形で出ないように）。

`(田中)` のように名前だけ書いて同名の点が複数あるとき、`辿る` は全部を起点にします。`結ぶ` と `消す` は**「どちらか分かりません」と候補を出して止まります**（取り違えると消えてしまうので）。

日本語入力のまま打てるよう、**全角の記号も受け付けます** — `（）［］｛｝：` と、文字列の `「…」`。

### まだ無いもの

条件式・集計・複数の線をつなぐパターンはありません。

## 保存のしかた

1 ファイルの追記型です。開くときに全件を読み、索引をメモリに作り直します。

```
先頭 8 バイト   E7 B5 90（「結」の UTF-8）+ "yui" + 00 + 版番号
以降            長さ(u32) 種別(u8) 本体 CRC32(u32)  …の繰り返し
種別            1 点を置く / 2 線を置く / 3 点を消す / 4 線を消す
```

整数はリトルエンディアンです。更新は同じ id で書き直し、**最後の記録を正**とします。

- **同じものを 2 回入れても増えません**（属性が上書きされます）。やり直しても重複しないようにするためです
- 点は「ラベルと名前の組」、線は「起点・種類・終点」が同じなら同じものとして扱います
- 属性の値は文字列・整数・小数の 3 種類です。ラベルを省いた点のラベルは `もの` になります
- **`消す` だけでは、ファイルから本文は消えません。**「消した」という記録が増えるだけです。
  `詰め直す` を実行すると、**生きている点と線だけを書いた新しいファイルに入れ替えて**、
  取り消した本文を落とします（点と線の id も 1 から振り直します）。
  入れ替える前に、書いたものを一度開いて読めることを確かめます。
  途中で失敗したら、元のファイルはそのままです
- 書きかけで落ちた末尾は、開くときに**捨てて**知らせます（別のファイルには残しません）。途中が壊れていたらエラーにして開きません
- **1 つのファイルを開けるのは 1 プロセスだけ**です（ファイルロック）。
  ★**ただし wasm では効きません。**emscripten の `flock` は何もしない作りなので、
  ネイティブと wasm が同じファイルを同時に書くと、**警告も出ないまま壊れます**
  （壊れ方は「途中の記録が読めません」で、そうなると開けません）

### 日本語の検索

文字列を 1 文字単位で 2-gram と 3-gram に分けて索引にします。辞書は使いません。

索引を作るときと探すときで**同じ揺れをそろえます** — 全角と半角の英数字、英字の大小、半角カナ、カタカナとひらがな（`キドク` で `きどく` が当たります）。**漢字の読みは扱いません。**

保存する文字列は元のままで、そろえるのは照合のときだけです。

## 大きさと速さ

**開く時間はファイルの大きさにほぼ比例し、メモリはファイルの 7〜8 倍**でした（下の条件で）。

| 点 | ファイル | 開く | 常駐（RSS） | 1MB あたり |
|---|---|---|---|---|
| 15,000 | 6.0 MB | 0.26 秒 | 48 MB | 0.043 秒 |
| 30,000 | 11.9 MB | 0.50 秒 | 90 MB | 0.042 秒 |
| 60,000 | 23.9 MB | 0.92 秒 | 177 MB | 0.039 秒 |
| 120,000 | 47.9 MB | 1.80 秒 | 353 MB | 0.038 秒 |

**測った条件**（2026-11-08・Linux・gcc `-O2`・他の作業と同じ機械なので揺れます）

- 1 点あたり属性 8 個・本文は 40 語ほど（1 点あたり 400 バイト前後）。3 点に 1 本 線を張る
- 開く時間は `同期` だけを実行した 3 回の最小値。常駐は `/usr/bin/time -f %M`

★**倍率は数字をそのまま信じないでください。本文が短いほど高くなります。**
点の数を 40,000 で固定して、本文の長さだけ変えて測った値です。

| 本文の語数 | ファイル | 常駐 | 倍率 |
|---|---|---|---|
| 2 | 1.9 MB | 32 MB | 17.1 倍 |
| 10 | 4.1 MB | 50 MB | 12.2 倍 |
| 40 | 12.4 MB | 82 MB | 6.7 倍 |
| 80 | 23.4 MB | 115 MB | 4.9 倍 |

**本文の長さを 40 倍にしてもファイルは 12.5 倍・常駐は 3.6 倍しか増えません。**
つまり**「小さい点が大量にある」形がいちばん重い**ので、倍率ではなく**点 1 つあたり**で
見積もってください（上の測定では 1 点あたり 800 バイト〜2.9 KB）。

#### 何にメモリを使っているか

剥がして測った内訳です（40,000 点・属性 8 個・本文 40 語。索引を作らない版と、
属性を持たない入力で同じ点数を開いて、差を取ったもの）。

| | 常駐 | 占める割合 | 1 点あたり |
|---|---|---|---|
| `探す` のための索引 | 38.9 MB | 38% | 1.0 KB |
| 属性（8 個） | 45.0 MB | 44% | 1.2 KB |
| 土台（点・名前・ラベル・つながりの表） | 19.3 MB | 19% | 0.5 KB |
| **合計** | **103.2 MB** | | **2.6 KB** |

- **索引と属性が同じくらい効いています。**片方だけ直しても半分です
- 属性 1 個あたり約 150 バイトで、**その多くは値そのものではなく、確保の単位ごとの負担**です
  （属性ごとにキーと値を別々に取っているため）
- 索引は**本文の文字数に比例**します（`index_text` が 2 文字・3 文字の並びを入れます）。
  名前だけのファイルでも 5.8 MB 使っていました（名前も索引に入ります）

**どちらもファイルの形には関係しないので、減らしても読めるファイルは変わりません。**

```sh
# 作って、開く時間だけを測る
yui big.yui < 命令.txt > /dev/null          # 書く
/usr/bin/time -f '%e 秒 / %M KB' yui big.yui 同期
```

★**wasm（emscripten）は native より遅いです。** 別の環境での実測では、**1MB あたりで 3 倍以上**かかっています。上の表は native の値です。

## 気をつけること

- **全件がメモリに載ります。** どれくらい膨らむかは[大きさと速さ](#大きさと速さ)にあります
- **トランザクションはありません。** `fsync` は `同期` と閉じるときだけです
- **Windows ではファイルの上限が 2 GB** です（`struct stat` の都合。詳しくは `yui_win.h`）
- **`詰め直す` の入れ替えの一瞬だけ、錠が外れます。**ファイルを閉じないと入れ替えられない
  （Windows の都合）ためです。その間に別のプロセスが開くと、両方が書ける状態になります。
  作業中は `<パス>.詰` を作るので、**置き場が一時的に倍ほど要ります**
- **1 つの `yui *` を複数のスレッドから同時に使わないでください**
- メモリが確保できないときはプロセスごと止まります（`abort`）
