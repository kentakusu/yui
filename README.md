# 結（yui）

[![テスト](https://github.com/kentakusu/yui/actions/workflows/ci.yml/badge.svg)](https://github.com/kentakusu/yui/actions/workflows/ci.yml)

日本語でそのまま問い合わせる、小さな組み込みグラフ DB です。C99 で書いてあり、外部のライブラリは使いません。

```
yui> 結ぶ (案件:結の開発)-[担当]->(人:田中)
(案件:結の開発)-[担当]->(人:田中)
作りました

yui> 辿る (人:田中)<-[担当]-(?案件)
(人:田中)<-[担当]-(案件:結の開発)
1 件
```

## これは何か

作者が自分の知識置き場に使うためのものです。**堅牢さも商用利用も考えていません。**

- **全部 日本語** — README・コメント・エラーメッセージ・問い合わせの言葉まで。国際化はしません
- **組み込みと単体の両方** — SQLite のように、ライブラリとしても CLI としても使えます
- **1 ファイルに保存** — `*.yui` を 1 つ持ち歩くだけです
- **辞書なしの日本語検索** — 文字の 2〜3-gram で部分一致します

**他の方が使われるなら「緩い前提」でお願いします。** 壊れても直す約束はしていません。

### 組み込むとき

`yui.c` と `yui.h`（Windows なら `yui_win.h` も）を自分のプロジェクトに入れて、一緒にコンパイルするだけです。`yui_cli.c` は CLI 用なので要りません。

```c
yui *db;
if (yui_open("知識.yui", &db) != YUI_OK) {
    fprintf(stderr, "%s\n", yui_errmsg(db));
}
yui_exec(db, "結ぶ (案件:結の開発)-[担当]->(人:田中)", 行ごとの関数, 文脈);
yui_close(db);
```

関数名だけは ASCII です（Swift や JNI から呼びやすいように）。

★**機械で読む形が要るなら `yui_exec_json` を使ってください。**`yui_exec` と同じですが、1 行を 1 つの JSON で返します（[機械で読む形](#機械で読む形--json)）。行の数と順は同じです。

★**`query` に NUL（文字コード 0）を入れないでください。** C の文字列として受け取るので、NUL があるとそこが終わりになり、そこから先は渡りません。文字列の途中に NUL があると「文字列が閉じていません」という、理由の分からないエラーになります。**バイト数で読んでいる側にしか分からないので、渡す前に数えてください**（`yui_cli.c` が実際にそうしています）。

★**wasm（emscripten）から呼ぶときは、長い問い合わせを `cwrap` の `'string'` 引数で渡さないでください。** スタックに積まれるので、**数千の文を 1 回で渡すと `memory access out of bounds` になります**。`_malloc` で確保して、ポインタを渡してください。

★**`yui_cb` が 0 以外を返すと、`yui_exec` に渡した残りの文が全部 実行されません。** 「返す行を N 件までにする」つもりで途中で止めると、後ろにある書き込みの文が黙って落ちます（戻り値は `YUI_OK` のままです）。数を絞りたいだけなら、0 を返し続けて受け取る側で捨ててください。

### 土台をまたいで 1 つのファイルを使うとき

`yui_open` の錠（POSIX は `flock`・Windows は `LockFileEx`・wasm は何もしない）は、**土台をまたぐと互いを排除しません**（[気をつけること](#気をつけること)）。

またぐなら **`yui_open_locked`** を使ってください。`<パス>.錠` を `O_EXCL` で作って排除します。**Windows・WSL2・wasm のどの組でも効くことを測っています**（[デーモンの構想](docs/デーモンの構想.md#測った土台の性質)）。

```c
yui *db;
char owner[1024];

/* 塞がれていたら、持ち主を名乗って断ります */
if (yui_open_locked("知識.yui", "my-app 1.2.3", 0, &db) != YUI_OK) {
    fprintf(stderr, "%s\n", yui_errmsg(db));   /* 錠の中身が入ります */
    yui_close(db);

    /* 開かずに持ち主を読んで、壊してよいか自分で決めます */
    if (yui_lock_owner("知識.yui", owner, sizeof owner) == YUI_OK && owner[0]) {
        /* 自分が前に落ちた残りだと分かったときだけ */
        yui_open_locked("知識.yui", "my-app 1.2.3", YUI_LOCK_BREAK, &db);
    }
}
```

★**`yui_open` の振る舞いは変わりません。**またがないなら今までどおりで構いません。錠を既定にすると「開けないことがある」が増えるので、使うと決めたときだけ呼んでください。

★**持ち主が落ちても錠は外れません**（`flock` は外れます）。結には「壊してよいか」が判断できません——pid の生死は同じ土台の中でしか見られず、「同じ機械か」も判定できないからです。**だから名乗り（第 2 引数）を必ず渡して、壊すかはアプリが決めてください。**

★**`詰め直す` の入れ替えの一瞬も、この `<パス>.錠` は外れません**（土台の錠〔`flock` / `LockFileEx`〕のほうは外れます。[気をつけること](#気をつけること)）。ただし守れるのは、**そのファイルを使う全員が `yui_open_locked` で開いているとき**だけです。

★**これは本番で実測されています**——実際に使われているファイルで初めて `詰め直す` が走ったとき、`<パス>.錠` の `since` と更新時刻が前後で動きませんでした。★**使っている人の実測で、こちらでは測っていません**（2026-11-09・Windows・1 台）。

## 使い方

```
yui 知識.yui              対話で使う
yui 知識.yui "探す 田中"    1 回だけ実行する
yui --json 知識.yui …      1 行を 1 つの JSON で出す（機械で読むとき）
yui --read 知識.yui …      読むだけで開く（★何本でも同時に読めます）
yui --wait 30 知識.yui …   塞がっていたら 30 秒 まで待つ
```

### 何本も同時に使うとき（`--read` と `--wait`）

結は 1 つのファイルを 1 プロセスで持つので、何も付けないと **2 本目は「別のところで開かれています」で終わります**（★**終了コード 3**。下記）。同じファイルを何本もの道具やセッションから使うなら、次の 2 つで足ります。

| | いつ使うか |
|---|---|
| **`--read`** | **引くとき。**錠を共有で取るので、**何本でも同時に読めます**（書く人だけが待ちます）。書き込む言葉（`作る` `結ぶ` `消す` `詰め直す`）は断ります |
| **`--wait 秒`** | **書くとき。**塞がっていたらその秒数まで待ちます |

```sh
yui --read 知識.yui "探す 会議"             # 引く。同時に何本でも
yui --wait 30 知識.yui "作る (メモ:思いつき)"  # 書く。混んでいたら待つ
```

★**`--read` で古い中身が返ることはありません。**読んでいる間は誰も書けないので、読んだものは必ずその時点の全部です。

★**自分で待ち直す仕組みを作らないでください。**理由で場合分けしようとすると、文面（`別のところで開かれています` / `別のところが錠を持っています`）を見ることになり、**文面が変わった日に黙って待たなくなります。**`--wait` なら理由を問わず待ちます。
自分で待ち直すなら、文面でなく**終了コード 3**を見てください（下記）。

★**`--wait` は待っている間 返りません。**使う側の持ち時間に収まる秒数にしてください。

★**`--wait` の秒数は「待つ上限」です。**プロセスの起動とファイルの読み込みは、それとは別にかかります。
★**待たされた時間を測るなら、空いているときに開く時間を引いてください。**
引かないと、**読み込みの遅いファイルが「長く待たされた」に見えます**（実際に読み違えた人が居ます）。

★**上限を少し 超えることはあります。**超えるのは**最後の 1 回の眠りの分だけ**で、
★**上限を長くしても超過は増えません**（残り時間は時計で数えています。
眠ったつもりの足し算で数えていたときは、**眠る回数に比例して超過が増えていました**）。
眠りの伸び方は土台次第なので、**数値は書きません。**持ち時間が厳しいなら、
自分の土台で 1 回 測ってください。

★**CLI は `<パス>.錠` を作りません。**錠は落ちても外れないので、何百回も起動するものが途中で落ちると残骸が全員を止めます。`flock` なら落ちれば外れます。土台をまたいで 1 つのファイルを使うなら、[埋め込み側で `yui_open_locked`](#土台をまたいで-1-つのファイルを使うとき) を使ってください。

★**無いファイルは作って開きます。**そのときは標準エラーに
`お知らせ: 新しいファイルとして始めました: …（中身がありませんでした）` と出ます。
**置き場を取り違えると「0 件」と同じ見た目になる**ので、こちらから言います
（`--json` のときは `{"kind":"notice","text":…}` で出ます）。

標準入力から流し込むこともできます。**誤りの行があっても止まらず、次の行へ進みます**（300 行 流して 1 行 間違っていたときに、残りを全部 捨てるほうが困るので）。失敗した行は `エラー: 2 行目: …` の形で標準エラーに出て、終了コードは 1 になります。

```sh
yui 知識.yui < 命令.txt
```

### 終了コード

| | 意味 | 再試行 |
|---|---|---|
| **0** | 通った | — |
| **1** | 失敗した（文法の誤り・壊れたファイル・権限など） | ★**しても同じ** |
| **2** | 使い方の誤り（知らない旗・引数が足りない） | ★**しても同じ** |
| **3** | ★**錠が取れなかった**（ほかが開いている・`--wait` で課めた） | ★**してよい** |

★**3 を別にしてあるのは、再試行を安全にするためです。**
1 と混ざっていると、呼ぶ側は**文法の誤りで途中まで書かれたものを、もう一度 流す**ことになります
（1 文目が正しく 2 文目が誤りのとき、**1 文目はファイルに残ります**）。

★**失敗の文面で場合分けしないでください。**文面はこちらの都合で変わります。
終了コード（埋め込んで使うなら `yui_busy()`）を見てください。

★**書き込みを丸ごと流し直しても安全です。**`作る` は上書き、
`結ぶ` は同じ線になる、`消す` は 2 回目が「消すものはありません」で 0 で返るのを測っています。
ただし ★**どこで止まったかを知りたいなら、標準入力から流してください**
（`エラー: 2 行目: …` の形で行番号が出ます。引数で渡したときは出ません）。

### 機械で読む形（`--json`）

`--json` を付けると、**1 行に 1 つの JSON**（JSON Lines）で出ます。行の数と順は人が読む形と同じです。

```sh
$ yui --json 知識.yui '一覧 (発言:) 見せる 日時,話者'
{"kind":"node","label":"発言","name":"x1","attrs":{"日時":"07:30","話者":"本人"}}
{"kind":"node","label":"発言","name":"x2","attrs":{"日時":"08:00","話者":"相手"}}
{"kind":"summary","text":"2 件","count":2}
```

**鍵は ASCII です。値（ラベル・名前・属性）は日本語のまま**入ります。関数名を ASCII にしているのと同じ理由で、読むのが機械だからです。

| `kind` | 中身 |
|---|---|
| `node` | `{"label":…,"name":…,"attrs":{…}}` |
| `edge` | `{"type":…,"from":{…},"to":{…},"attrs":{…}}` |
| `path` | `{"nodes":[…],"edges":[{"type":…,"forward":真偽,"attrs":{…}}]}`（`辿る` の道。`nodes` は `edges` より 1 つ多い） |
| `link` | `{"dir":"out"\|"in","type":…,"attrs":{…},"other":{…}}`（`見る` のつながり） |
| `text` | `{"text":…}`（`手引き` など、人へのそのままの 1 行） |
| `summary` | `{"text":…}`。件数が分かるときは `"count"` も入る |

- **文字列は JSON として逃がされます。** 本文に改行や引用符が入っていても、読む側で戻す必要はありません
- **数は数のまま**出ます（`"順":1`・`"重み":0.5`）。引用符は付きません
- 失敗は標準エラーに `{"kind":"error","line":2,"text":…}` の形で出ます（流し込みのときは `line` 付き）
- `名前だけ` や `見せる` はそのまま効きます（`attrs` が絞られます）

★**`jq` で日本語の属性名を引くときは `["…"]` で囲んでください。** 点のあとに続ける書き方は**構文エラーになります**（jq 1.7 で確認）。

```sh
jq -r '.attrs.本文'      # → jq: error: syntax error …
jq -r '.attrs["本文"]'   # → あいう
```

鍵が ASCII のところ（`kind`・`label`・`name`・`attrs`・`count`）は点で続けられます。

```sh
# 書いたあとに件数を数え直す
yui --json 知識.yui '一覧 (発言:) 名前だけ' \
  | jq -s 'map(select(.kind=="summary"))[0].count'
```

標準入力が端末でなければ、1 行ずつ実行します。

```
yui 知識.yui < 命令.txt
```

## デーモン（同時に読む）

結は「1 つのプロセスが開いて、閉じるまで持つ」形なので、同じファイルを複数のプロセスから使えません。`yuid` が 1 つだけ持ち、口（`127.0.0.1` の TCP）を通して何人にも読ませます。

```sh
make yuid                       # Linux / macOS（Windows は build.bat）
./yuid 知識.yui --port 39200 --idle 600
```

★**いまは読むだけです。**書けるようにするのは次の段で、そのとき「誰が・いつ」をデーモンが押します。設計と段取りは[デーモンの構想](docs/デーモンの構想.md)が正です。

やりとりは**長さを先に送って、1 行 1 つの JSON が返る**形です。

```
送る:  12\n一覧 (人:)
返る:  {"kind":"node","label":"人","name":"田中","attrs":{"役職":"部長"}}
       {"kind":"summary","text":"1 件","count":1}
       {"kind":"end","rc":0}
```

★**締めの行（`end`）があるのは、結の出力に「必ず最後に出る行」が無いからです**（`手引き` は `summary` を出さず、`終わる` は何も出しません）。**`end` が来るまで読んでください。**`rc` は 1 つでも失敗があれば 1 です。

★**1 本の接続で何度でも問い合わせられます。**繋ぎ直すと、LAN 越しでは倍 かかります（[実測](docs/デーモンの構想.md#測った土台の性質)）。

★**`終わる` は接続を切るだけです。**デーモンは止まりません（止めるのは Ctrl-C か `--idle` の空き時間切れ）。

★**問い合わせは CLI と同じく 1 行ずつ実行します。**行の分け方が CLI と違うと、引用符の中の生の改行の扱いが変わるためです。

### 返りの上限（`--max-rows`）

**既定は 1 回の問い合わせで 10000 行まで**です。超えたら打ち切り、**必ずそう言います。**

```json
{"kind":"error","text":"返りが 10000 行を超えたので打ち切りました。この問い合わせの残りの行も実行していません。「新しい N」で絞ってください"}
{"kind":"end","rc":1,"cut":true}
```

★**黙って切りません。**黙って切ると、受け取った側は「これで全部」と読みます（気づけない欠配）。`--max-rows 0` で上限を外せます。

★**打ち切ると、その問い合わせの残りの行も実行しません。**`end` の `"cut":true` で分かります。

### 気をつけること（デーモン）

- ★**デーモンを立てている間、CLI からは同じファイルを開けません。**デーモンが錠を持ちます。**全員がデーモンを通るか、全員が CLI を使うかの、どちらかです**
- 同時に繋げるのは 16 本までです（超えたら理由を言って断ります）
- **読まないクライアントで止まりません。**待たずに送り、溜まりが 1 MB を超えたらその接続から新しい問い合わせを読まず、**`--max-out`（既定 8 MB）を超えたらその接続を切ります**（他のクライアントを守るため。切ったことは標準エラーに出ます）
- ★**公平さはありません。**1 本で順に回すので、重い問い合わせの間は他が順番を待ちます（止まるのではなく、待つだけです）
- ★**`127.0.0.1` にしか出しません。**`networkingMode=Mirrored` の環境では、これで Windows と WSL2 の両方から使えます（既定の NAT では共有されません）
- ★**異常終了すると `<パス>.錠` が残ります。**合図（Ctrl-C / SIGTERM）を受けたときは外します

## 言葉

1 行が 1 文です。行末の `。` はあってもなくても構いません。`#` から行末はコメントです。

| 言葉 | すること | 例 |
|---|---|---|
| `作る` | 点を作る | `作る (人:田中 {役職: "部長", 年齢: 42})` |
| `結ぶ` | 線を結ぶ（点が無ければ作る） | `結ぶ (案件:結の開発)-[担当 {開始: "2026-11"}]->(人:田中)` |
| `探す` | 文字列の部分一致 | `探す "既読"` / `探す "既読" (メモ:)` |
| `辿る` | つながりを辿る | `辿る (人:田中)<-[担当]-(?案件)` |
| `見る` | 属性とつながりの一覧 | `見る (人:田中)` |
| `一覧` | そのラベルの点すべて | `一覧 (人:)` |
| `消す` | 点や線を消す（★**中身はファイルに残ります**。[下記](#保存のしかた)） | `消す (人:田中)` |
| `詰め直す` | 取り消した記録をファイルから落とす | `詰め直す` |
| `同期` | ここまでを書き出す | `同期` |
| `手引き` | 使い方を出す | `手引き` |
| `終わる` | 終わる | `終わる` |

★`結ぶ` は**点が無ければ作ります**。作ったときは締めの行で知らせます（`作りました（端の点も 2 つ 作りました）`）。名前を打ち間違えると、属性の無い点が増えるためです。

★`探す`・`辿る`・`一覧` の末尾には**修飾**を書けます（[新しい順に N 件](#新しい順に-n-件)・[名前だけ](#名前だけ)・[見せる](#見せる-ab)。[まとめ](#修飾のまとめ)）。

★`見る` の締めの「N 件」は**点の数**です。つながりの行がいくつ出ても、1 つの点を見たなら `1 件` になります。

★`探す` が探すのは**書かれている文字そのもの**です。**漢字の読みでは当たりません** — `探す "かいぎょう"` で `改行` は見つかりません。かな・英数字の揺れはそろえます（[日本語の検索](#日本語の検索)）。

#### `探す` が見ている範囲

| | |
|---|---|
| 当たる | 点の名前・**点の属性の値**・**線の属性の値** |
| 当たらない | 点のラベル・線の種類 |

**線も返ります。** `探す "さくら"` は、本文に「さくら」が入った点と、`-[宛て {理由: "さくら"}]->` のような線の両方を返し、どちらも 1 件に数えます。

**点だけが欲しいときは、点の形を書きます。**

```
探す "さくら"          # 点も線も
探す "さくら" (便:)     # (便:…) の点だけ。線は返りません
```

★**ラベルは探しません。** `(上げる:…)` という点が在っても `探す "上げる"` は 0 件です。代わりに、**0 件のときだけ締めの行で知らせます**。

```
> 探す "上げる"
0 件（「上げる」は点の種類です。一覧 (上げる:) で引けます）
```

ラベルを探す対象に入れれば当たるようになりますが、同じラベルの点が何万と並ぶ使い方では索引がその分だけ太るので、**メモリを増やさずに迷いを解く**ほうを選びました。

### 括弧の読み方

ここを書き分けるのが、この言葉の肝です。

| 書き方 | 意味 |
|---|---|
| `(田中)` | その名前の点（ラベルは問わない） |
| `(人:田中)` | 種類つきの点 |
| `(人:)` | その種類のどれでも |
| `(?相手)` | 誰でも。結果を受け取る変数になる |
| `()` | 何でも |

線の向きは `->`・`<-`・`-`（両方）です。段数を足すと多段で辿ります。

```
辿る (私)-[返信 3段]->(?相手)     # 3 段先まで
辿る (私)-[]->()                 # 種類も相手も問わない
```

★**線の側に変数はありません。**点の `(?相手)` は「誰でも」の印ですが、`[?]` は
**「種類が『?』という名前の線」**を探してしまいます。種類を問わないなら `[]` です。
間違えても 0 件 のときに知らせます（`0 件（「[?]」は種類が「?」の線です。種類を問わないなら [] です）`）。

### 新しい順に N 件

`探す`・`辿る`・`一覧` の末尾に `新しい N` と書くと、**新しい順に N 件**だけ返します。付けなければ今までどおり、古い順に全件です。

```
一覧 (便:) 新しい 20
辿る (人:田中)<-[宛て]-(?便) 新しい 20
探す "見積" (便:) 新しい 20
```

★**「新しい」は時刻を見ません。点の id の大きい順です。** 結は追記しかせず、id は書いた順に振られるので、**id が大きい＝後に書いた**が常に成り立ちます（`詰め直す` で振り直しても、生きている点を順に書くので順序は保たれます）。**属性に書いた `時刻` では並びません。**

★**返す数であって、見る数ではありません。** `辿る` は全部 歩いてから N 件 返します。先に打ち切ると、あとで見つかるはずの新しい点を落とすためです。

★**入口が 2 つ以上あるときは気をつけてください。** 2 つの流し込みを順に書くと（先に A を全部、次に B を全部）、**id の順と時刻の順がずれます**。新しい順に出したいなら、**書く前に時刻の順に並べてから流してください**。

★**`探す` に付けるときは、点の形も書いてください。** 絞らない `探す` は線も返しますが、点の id と線の id は別の数直線なので、混ざったものを新しい順に並べられません。

```
探す "見積" 新しい 20          # エラー。並べられません
探す "見積" (便:) 新しい 20     # これなら並びます
```

`見る` には付きません（1 つの点を見る言葉なので）。

### 名前だけ

末尾に `名前だけ` と書くと、**属性を出さず、ラベルと名前だけ**返します。`新しい N` と一緒にも書けます（順序は問いません）。

```
一覧 (メモ:) 名前だけ
探す "見積" (便:) 新しい 20 名前だけ
辿る (人:田中)<-[宛て]-(?便) 名前だけ
```

**本文を属性に入れていると、1 件で何百 KB にもなります。** 結果を見て「どれを開くか」決めるだけなら、名前だけで足ります。使う側が文字列を切り分けて名前を取り出す必要もなくなります。

★**点の属性も線の属性も消えます。** `辿る` は線の属性を出す言葉なので、そこでも効きます。

`見る` には付きません（属性とつながりを見る言葉なので）。

### 見せる a,b

末尾に `見せる` と属性の名前を並べると、**その属性だけ、並べた順に**出します。

```
一覧 (発言:) 見せる 日時,話者
探す "見積" (便:) 新しい 20 見せる 日時
辿る (日:2026-11-08)-[含む]->(?発言) 見せる 順
```

**名前に意味が無いとき**（取り込み元が振った id など）は、`名前だけ` ではどれが何か分かりません。属性を 1〜2 個 添えれば、1 件ずつ `見る` を打たずに済みます。

- **並べた順に出ます**（点が持っている順ではありません）
- **持っていない属性は黙って飛ばします。** 点ごとに持ち物が違うのが普通なので、エラーにはしません
- 並べられるのは **16 個**までです
- `名前だけ` と一緒には書けません（どちらも属性の出し方を決めるので）

★**`辿る` では、辿り着いた点の属性にも効きます。**

```
辿る (日:2026-11-08)-[含む]->(?発言)
  (日:2026-11-08)-[含む {順: 1}]->(発言:x1)

辿る (日:2026-11-08)-[含む]->(?発言) 見せる 日時,話者
  (日:2026-11-08)-[含む]->(発言:x1 {日時: "07:30", 話者: "本人"})
```

`辿る` は**既定では点の属性を出しません**（道が主役の行なので、全部 並べると形が読めなくなります）。`見せる` で名前を挙げたときだけ、その属性が点にも出ます。線と点の属性を一緒に挙げてもかまいません（`見せる 日時,順`）。

### 修飾のまとめ

| 修飾 | すること |
|---|---|
| `新しい N` | 新しい順に N 件だけ返す |
| `名前だけ` | 属性を出さない |
| `見せる a,b` | その属性だけ、並べた順に出す |

`探す`・`辿る`・`一覧` に付けられます。**順序は問いません**し、`新しい N` は `名前だけ` / `見せる` と組み合わせられます。同じ修飾を 2 回 書くとエラーです（打ち間違いが「効かなかった」の形で出ないように）。

`(田中)` のように名前だけ書いて同名の点が複数あるとき、`辿る` は全部を起点にします。`結ぶ` と `消す` は**「どちらか分かりません」と候補を出して止まります**（取り違えると消えてしまうので）。

日本語入力のまま打てるよう、**全角の記号も受け付けます** — `（）［］｛｝：` と、文字列の `「…」`。

### まだ無いもの

条件式・集計・複数の線をつなぐパターンはありません。

## 保存のしかた

1 ファイルの追記型です。開くときに全件を読み、索引をメモリに作り直します。

```
先頭 8 バイト   E7 B5 90（「結」の UTF-8）+ "yui" + 00 + 版番号
以降            長さ(u32) 種別(u8) 本体 CRC32(u32)  …の繰り返し
種別            1 点を置く / 2 線を置く / 3 点を消す / 4 線を消す
```

整数はリトルエンディアンです。更新は同じ id で書き直し、**最後の記録を正**とします。

- **同じものを 2 回入れても増えません**（属性が上書きされます）。やり直しても重複しないようにするためです
- 点は「ラベルと名前の組」、線は「起点・種類・終点」が同じなら同じものとして扱います
- 属性の値は文字列・整数・小数の 3 種類です。ラベルを省いた点のラベルは `もの` になります
- **`消す` だけでは、ファイルから本文は消えません。**「消した」という記録が増えるだけです。
  ★**だから `消す` の知らせにも、そのことを書いています**
  （`点を 1 件と、つながる線を 0 本 消しました（中身はファイルに残ります。落とすには 詰め直す）`）。
  **誤って秘匿のものを書いたとき「消えた」と読んで手を止めてしまう**ので、
  文書ではなく出力の側に置いてあります（手当ての順は[秘匿のものの置き方](docs/秘匿のものの置き方.md)）。
  `詰め直す` を実行すると、**生きている点と線だけを書いた新しいファイルに入れ替えて**、
  取り消した本文を落とします（点と線の id も 1 から振り直します）。
  入れ替える前に、書いたものを一度開いて読めることを確かめます。
  途中で失敗したら、元のファイルはそのままです
- 書きかけで落ちた末尾は、開くときに**捨てて**知らせます（別のファイルには残しません）。途中が壊れていたらエラーにして開きません
- **1 つのファイルを開けるのは 1 プロセスだけ**です（ファイルロック）。
  ★**ただし wasm では効きません。**emscripten の `flock` は何もしない作りなので、
  ネイティブと wasm が同じファイルを同時に書くと、**警告も出ないまま壊れます**
  （壊れ方は「途中の記録が読めません」で、そうなると開けません）

### 日本語の検索

文字列を 1 文字単位で 2-gram と 3-gram に分けて索引にします。辞書は使いません。

索引を作るときと探すときで**同じ揺れをそろえます** — 全角と半角の英数字、英字の大小、半角カナ、カタカナとひらがな（`キドク` で `きどく` が当たります）。**漢字の読みは扱いません。**

保存する文字列は元のままで、そろえるのは照合のときだけです。

## 大きさと速さ

**開く時間はファイルの大きさにほぼ比例し、メモリはファイルの 5〜6 倍**でした（下の条件で）。

| 点 | ファイル | 開く | 常駐（RSS） | 1 点あたり |
|---|---|---|---|---|
| 15,000 | 6.0 MB | 0.20 秒 | 35 MB | 2.4 KB |
| 30,000 | 11.9 MB | 0.48 秒 | 67 MB | 2.3 KB |
| 60,000 | 23.9 MB | 0.91 秒 | 131 MB | 2.2 KB |
| 120,000 | 47.9 MB | 1.42 秒 | 259 MB | 2.2 KB |

**測った条件**（2026-11-08・Linux・gcc `-O2`・他の作業と同じ機械なので揺れます）

- 1 点あたり属性 8 個・本文は 40 語ほど（1 点あたり 400 バイト前後）。3 点に 1 本 線を張る
- 開く時間は `同期` だけを実行した 3 回の最小値。常駐は `/usr/bin/time -f %M`

★**倍率は数字をそのまま信じないでください。本文が短いほど高くなります。**
点の数を 40,000 で固定して、本文の長さだけ変えて測った値です。

| 本文の語数 | ファイル | 常駐 | 倍率 | 1 点あたり |
|---|---|---|---|---|
| 2 | 1.9 MB | 27 MB | 14.5 倍 | 0.7 KB |
| 10 | 4.1 MB | 38 MB | 9.3 倍 | 1.0 KB |
| 40 | 12.4 MB | 66 MB | 5.3 倍 | 1.7 KB |
| 80 | 23.4 MB | 93 MB | 4.0 倍 | 2.4 KB |

**本文の長さを 40 倍にしてもファイルは 12.5 倍・常駐は 3.5 倍しか増えません。**
つまり**「小さい点が大量にある」形がいちばん重い**ので、倍率ではなく**点 1 つあたり**で
見積もってください。

#### 何にメモリを使っているか

剥がして測った内訳です（40,000 点・属性 8 個・本文 40 語。索引を作らない版と、
属性を持たない入力で同じ点数を開いて、差を取ったもの）。

| | 常駐 | 占める割合 | 1 点あたり |
|---|---|---|---|
| 属性（8 個） | 38.3 MB | 48% | 1.0 KB |
| `探す` のための索引 | 22.9 MB | 29% | 0.6 KB |
| 土台（点・名前・ラベル・つながりの表） | 18.1 MB | 23% | 0.5 KB |
| **合計** | **79.3 MB** | | **2.0 KB** |

- 索引は**本文の文字数に比例**します（`index_text` が 2 文字・3 文字の並びを入れます）。
  名前だけのファイルでも 3.4 MB 使っていました（名前も索引に入ります）

★**日本語の文章が多いファイルでは、索引が常駐の大半になります。**上の表は
「同じ語を並べた本文」で測ったものなので、索引が軽く出ています。実際の文章は
2〜3 文字の並びの種類が桁違いに多く、**ある実ファイル（2.2 MB）では索引が常駐の
82% を占めていました**。文字をばらけさせて測ると、この形になります。

| | 常駐 |
|---|---|
| 文字をばらけさせた本文・2.2 MB・点 104 | 77 MB |
| 同じ語を並べた本文・2.6 MB・点 104 | 7 MB |

**同じ大きさのファイルでも 10 倍 違います。**見積もるときは、**本文の文字の
ばらけ方**で変わると思ってください。
- **ファイルの形には関係しない話なので、ここを減らしても読めるファイルは変わりません**
  （減らしたときに、バイトが同じことと答えが同じことを測って確かめています）

```sh
# 作って、開く時間だけを測る
yui big.yui < 命令.txt > /dev/null          # 書く
/usr/bin/time -f '%e 秒 / %M KB' yui big.yui 同期
```

★**wasm（emscripten）は native より遅いです。** 別の環境での実測では、**1MB あたりで 3 倍以上**かかっています。上の表は native の値です。

## 気をつけること

- **全件がメモリに載ります。** どれくらい膨らむかは[大きさと速さ](#大きさと速さ)にあります
- **トランザクションはありません。** `fsync` は `同期` と閉じるときだけです
- **Windows ではファイルの上限が 2 GB** です（`struct stat` の都合。詳しくは `yui_win.h`）
- **`詰め直す` の入れ替えの一瞬だけ、土台の錠（`flock` / `LockFileEx`）が外れます。**
  ★**`<パス>.錠` のほうは外れません**（上の[土台をまたいで 1 つのファイルを使うとき](#土台をまたいで-1-つのファイルを使うとき)）。
  外れるのは、ファイルを閉じないと入れ替えられない
  （Windows の都合）ためです。その間に別のプロセスが開くと、両方が書ける状態になります。
  作業中は `<パス>.詰` を作るので、**置き場が一時的に倍ほど要ります**。
  ★`yui_open_locked` で開いていれば、この窓は `<パス>.錠` が塞ぎます
  （そのファイルを使う全員がそうしているときだけです）
- ★**錠は土台をまたぎません。** POSIX の `flock` と Windows の `LockFileEx` は互いを
  排除せず、wasm では `flock` は何もしないスタブです。つまり**同じファイルを、Windows から・
  WSL2 から `/mnt/...` 越しに・wasm から開くと、どの 2 つでも「自分が持ち主だ」と思ったまま
  同時に書けます**（実測は [デーモンの構想](docs/デーモンの構想.md#測った土台の性質)）。
  **またぐなら `yui_open_locked` を使ってください**（[土台をまたいで 1 つのファイルを使うとき](#土台をまたいで-1-つのファイルを使うとき)）。
  `yui_open` のままにするなら、「同時に開かない」を手で守ってください
- ★**秘匿の印はありません。**ファイルには平文で入るので、印を付けても `strings` でも `探す` でも出ます。秘匿のものは**別のファイルに分けて**ください（[秘匿のものの置き方](docs/秘匿のものの置き方.md)）。
  新しいファイルは 644 で作りますが、**持ち主が狭めた権限は詰め直しても広げません**
- **1 つの `yui *` を複数のスレッドから同時に使わないでください**
- メモリが確保できないときはプロセスごと止まります（`abort`）

## これから

- **開くときのメモリをもう一段 減らす** — 残っている当てどころは 2 つです。①属性のキー（`本文` `日時` …）を点ごとに持っているので、共有すれば減ります（点が多いファイルに効きます）②索引の表そのもの（並びの種類 × 24 バイト）。日本語の文章が多いファイルでは、ここが常駐のいちばん大きい項目です
- CLI の対話（端末）のテスト（終了コードと標準入力の読み方は `tests/cli.sh` が見ています）
- `詰め直す` が**書いている途中で**失敗する道のテスト（置き場を尽きさせる手が、土台をまたいで作れていません。作れない・入れ替えられない・既にある は見ています）
- iOS・Android でのビルド確認
- **デーモン越しに書けるようにする**（＋「誰が・いつ」をデーモンが押す）— 読むだけの
  ものは[入りました](#デーモン同時に読む)。段取りと測った土台の性質は
  [デーモンの構想](docs/デーモンの構想.md)にあります
- **デーモンの公平さ** — 1 本で順に回すので、重い問い合わせの間は他が待ちます（止まるのではなく、順番を待つだけです）。
  ★**返りの上限（`--max-rows`）と、読まない相手で止まらない作りは入りました**
