# デーモンの構想

**状態: 構想です。実装はまだありません。**

この文書が答えるのは「結を常駐のプロセス（デーモン）にするなら、何が要るか」です。
決まったことではなく、決めるために必要な材料と、測った土台の性質を置いてあります。

実装に入るときは、この文書の「段取り」から順に進め、**段ごとに決着を書き足してください**
（やらないと決めたものも、理由ごと書いてください。理由の無い「やらない」は、次に読む人が同じ提案を蒸し返します）。

---

## なぜ要るか

いまの結は **1 つのプロセスがファイルを開いて、閉じるまで持つ**形です。
これで足りなくなるのは、次の 3 つが重なったときです。

1. **複数のプロセスが同じファイルを使いたい**
2. **複数の機械（同じ LAN の中）から使いたい**
3. **プロセスが絶えず建て直される** — 記憶がプロセスより長く生きる必要がある

★**3 が本当の理由です。**「開くのを 1 回で済ませたい」という速さの話ではありません。
48 MB のファイルを開くのは 1.4 秒ほどで（[大きさと速さ](../README.md#大きさと速さ)）、
使う側が常駐しているなら、デーモンにしても速くはなりません。

デーモンが与えるのは**同時に使えること**と**プロセスが消えても記憶が残ること**です。

## 測った土台の性質

設計がここに乗っているので、**先に読んでください。**
値はすべて 2026-11-08（JST）に測ったものです。取り直すコマンドを併記します。

### 1. 錠は土台をまたぎません

結は POSIX で `flock`、Windows で `LockFileEx` を使います（`yui_win.h`）。
**この 2 つは互いを排除しません。**Windows の見えているディスクを WSL2 から
`/mnt/...` 越しに開いた場合（9p）に当たります。

| 先に掴む側 | あとから試す側 | 結果 |
|---|---|---|
| Windows（`LockFileEx`） | WSL2（`flock`） | **素通り**（取れてしまう） |
| WSL2（`flock`） | Windows（`LockFileEx`） | **素通り**（取れてしまう） |
| WSL2（`flock`） | WSL2（`flock`） | 弾かれる（＝`flock` 自体は効いている） |

3 行目が陽性対照です。`/mnt/...` の上でも WSL2 の中の ext4 の上でも弾かれるので、
**素通りしているのは土台をまたいだときだけ**と言えます。

取り直すコマンド（`F` に、Windows から見えるディスクの上のファイルを入れてください）:

```sh
# WSL2 側で掴んだまま
flock -x "$F" -c "sleep 10" &
# Windows 側（PowerShell）で試す。例外が出なければ素通り
#   $fs=[IO.File]::Open($F,'Open','ReadWrite','ReadWrite'); $fs.Lock(0,1024)
```

```sh
# 陽性対照（同じ側で 2 回）。2 つ目が rc=1 なら flock は効いている
flock -x "$F" -c "sleep 3" & sleep 0.6
flock -n -x "$F" -c true; echo "rc=$?"
```

★**wasm（emscripten）では `flock` は何もしないスタブです。**
つまり穴は 2 つあり、**土台が 3 つ以上あるときは `flock` だけでは足りません。**

★**いちばん危ないのは `詰め直す` です。**
`<パス>.詰` を作って入れ替える間に別のプロセスが追記していると、
**その追記は黙って消えます。**エラーは出ません。

### 2. `O_EXCL` でのファイル作成はまたぎます

**土台 3 つ（Windows・WSL2・wasm）のすべての組で、両方向とも排除できました。**

| 先に作る側 | あとから試す側 | 結果 |
|---|---|---|
| WSL2（`O_EXCL`） | Windows（`CREATE_NEW`） | **弾かれる** |
| Windows（`CREATE_NEW`） | WSL2（`O_EXCL`） | **弾かれる** |
| wasm（`O_EXCL`） | Windows / WSL2 | **弾かれる** |
| WSL2（`O_EXCL`） | wasm | **弾かれる** |
| 同じ側で 2 回目 | — | 弾かれる（＝対照） |

★**wasm の行は `-sNODERAWFS=1` のときの値です。`MEMFS` では仮想のファイル系の中で
閉じるので、錠になりません。**ビルドの引数を先に確かめてください。

★**`EEXIST` の値が土台で違います。**emscripten は **20**、Linux は **17** です。
`errno == EEXIST` と書けば合いますが、**数字を直に書くと wasm で外れます。**
土台をまたいで errno の数字を報告し合うときも、同じ理由で食い違います。

取り直すコマンド:

```sh
set -C; : > "$F.錠"      # WSL2 側。2 回目は cannot overwrite になる
# Windows 側: [IO.File]::Open("$F.錠",'CreateNew','Write','None') が例外を投げる
# wasm 側: open(..., O_WRONLY|O_CREAT|O_EXCL, 0644) を 2 回。2 回目が -1 / EEXIST
```

★ wasm の行は、**wasm で結を使っている側が打ち直した値**です
（この文書を書いた側は wasm を走らせていません）。
★ その測定の限界も申し送られています: **同じビルド引数の別の小さなプログラムで測ったもので、
本体のワーカーそのものからではない**／**9p の 1 つのドライブでしか測っていない。**

★**代償があります。`O_EXCL` の錠は、持ち主が落ちても外れません。**
`flock` は落ちれば自動で外れます。**だから両方 持つのが正解で、どちらかではありません。**

- `flock` — 同じ土台の中。落ちれば外れる
- `<パス>.錠`（`O_EXCL`）— 土台をまたぐ。**中身に「機械名・pid・いつから」を書く**

★ 残骸の掃除が要ります。**次に来たプロセスが「中身を見て、持ち主が生きているか確かめてから」乗っ取る**規則を決めてください。
`O_EXCL` は原子的なので、**同時に複数が乗っ取りを試しても、成功するのは 1 つだけ**です。

### 3. Windows と WSL2 は loopback を共有できます

★**これは設定に依存します。**`networkingMode=Mirrored`（`.wslconfig`）かつ
`hostAddressLoopback=true` のときに成り立ちます。**既定の NAT では成り立ちません。**

| 待つ側 | 繋ぐ側 | 結果 |
|---|---|---|
| Windows の `127.0.0.1` | WSL2 | 通る |
| WSL2 の `127.0.0.1` | Windows | 通る |
| 誰も待っていないポート | — | 接続拒否（＝対照） |

今の設定を見るコマンド:

```sh
grep -E "networkingMode|hostAddressLoopback" "$USERPROFILE/.wslconfig"
```

**効いてくること**: この設定なら、**`127.0.0.1` で待つ 1 本のデーモンが
Windows と WSL2 の両方に出せます。**Unix ソケットも名前付きパイプも要りません。

★**副作用: ポート番号も共有されます。**Windows と WSL2 が同じポートを取り合うので、
**2 本 立てようとすると必ず片方が `bind` に失敗します。**
これは「デーモンは 1 本だけ」という設計には都合がよい性質です。

★ NAT（既定）のときは共有されないので、**土台ごとに口を用意する**必要があります
（Windows は名前付きパイプ、WSL2 は Unix ソケット）。**どちらの設定かを先に見てください。**

### 4. 口を 1 つに保つ仕掛けは、土台で意味が逆になる

`SO_REUSEADDR` を**付けるか付けないか**が、土台で逆の意味を持ちます。

| | 実測したこと |
|---|---|
| POSIX・付けない | ★**止めた直後に同じポートで建て直せません**（TIME_WAIT。テストで踏みました） |
| POSIX・付ける | 建て直せます。**そして生きている待ち受けは 2 つ 作れません**（テストで確認） |
| Windows・`SO_EXCLUSIVEADDRUSE` | 2 本 目は `bind` で失敗します（手元の Windows で確認） |

★**Windows の `SO_REUSEADDR` は、2 つ目の `bind` も通してしまう**と言われています
（横取り）。**これは実測していません。**だから Windows では付けず、
`SO_EXCLUSIVEADDRUSE` を付けています。**測っていないことを根拠にしているのはここだけです。**

⇒ **POSIX は `SO_REUSEADDR` を付ける、Windows は付けずに `SO_EXCLUSIVEADDRUSE` を付ける。**
**横展開しないでください。**

### 5. LAN の往復は、同じ機械の中の 6〜13 倍

| 測ったもの | 最小 | 中央 | 最大 |
|---|---|---|---|
| 同じ機械の中（loopback）・接続して 1 行 読む | 0.79 ms | **0.95 ms** | 27.94 ms |
| LAN 越し・**毎回 接続し直す** | 11.72 ms | **12.44 ms** | 117.47 ms |
| LAN 越し・**持続接続の 1 往復** | 5.60 ms | **6.09 ms** | 119.43 ms |

**測った条件**（2026-11-08 JST）: 同じルータに繋がった別の機械へ Wi-Fi 越し。
20〜40 回の分布。相手側で待ち受けを立ててもらって測ったので、**片側だけでは測れません。**

**ここから出る決めごとが 3 つあります。**

1. ★**持続接続にしてください。**接続し直す作りにすると倍 かかります（12.44 対 6.09）。
   小さい問い合わせ 20 件なら **249 ms 対 122 ms**、同じ機械なら 19 ms です
2. ★**1 往復に複数の文を載せられることが効きます。**
   結の言葉はもともと改行で複数の文を渡せるので、**そこがそのまま効きます**
3. ★**最大は持続接続でも 119 ms まで振れます。**Wi-Fi のゆらぎで、デーモンのせいではありません。
   **だから「クライアントが読むのを待って止まる」作りにすると、網のゆらぎが
   そのまま全員の詰まりになります**（下の「詰まり」の 2 行目が必須な理由）

★ あわせて分かったこと: **2 つの機械の時計が 3 秒 ずれていました**
（同じ 20 回の接続を、相手は 18:15:51、こちらは 18:15:54 と記録）。
**これが、時刻をデーモンに押させる理由です**（下記）。

## 錠は 3 つに分かれます

混ぜると設計が壊れるので、別の名前で呼んでください。

| | 何を守るか | 手 |
|---|---|---|
| **① ファイルの持ち主** | 2 つのプロセスが同じファイルに書かないこと | `flock` ＋ `<パス>.錠`（`O_EXCL`） |
| **② デーモンが 1 本だけ** | 2 つのデーモンが立たないこと | 口の `bind` が排他になる（上の副作用）。別土台のときは `<パス>.錠` と同じ手 |
| **③ 中の順番** | 問い合わせが混ざらないこと | ★**並行にしない**（下記） |

★**③ は「並行にしない」を推します。**`yui.h` が既に
「1 つの `yui *` を複数のスレッドから同時に使わないでください」と決めているので、
**デーモンの中で並行にするには、その約束を変えるところから始めることになります。**
まず 1 本で回し、**詰まることを測ってから**考えてください（詰まり方の見当は下記）。

## 口（どこで待つか）

口は 2 つ持ち、**外に出る口は既定で閉じます。**

| 口 | 届く相手 | 合言葉 |
|---|---|---|
| `127.0.0.1` | その機械と、その中の WSL2 | 不要 |
| LAN のアドレス | 同じ LAN の別の機械 | ★**必須** |

★**LAN の口に合言葉を必須にする理由は、privacy です。**
結のファイルには、使う人の記録が丸ごと入りえます。
**口が開いていれば、同じ LAN に居る誰でも全部 読めます。**

- 合言葉は**リポジトリに入れないところ**に 1 ファイル置き、繋いだ直後に送らせる
- **Windows の着信は既定で拒否**です（ファイアウォールの `DefaultInboundAction`）。
  ★**明示の許可が要るのは手間ではなく関所です。**いつ誰が開けたかが記録に残ります
- ★**TLS は要るか**を決めていません。同じ LAN の中でも、合言葉が平文で流れます。
  **決める前に、その LAN に誰が居るかを数えてください**（下記「測っていないこと」）

## 問い合わせの形

★**いまの言葉と `--json` が、そのまま protocol になります。**別の形式を作る必要はありません。

ただし 2 つ、足りないものがあります。

### 1. 締めの行が、必ず出るとは限りません

```
作る / 一覧 / 同期   → summary の行が出る
手引き               → summary が無い（text の行で終わる）
終わる               → 何も出ない
```

★**だから「summary が来たら 1 件ぶん終わり」では組めません。**
**終わりを表す行を足してください。**

```json
{"kind":"end","rc":0}
```

### 2. 行の分け方を CLI と同じにしてください

★**引用符の中の生の改行を拒んでいるのは、ライブラリではなく CLI の行分けです。**
デーモンが受け取った塊をそのまま `yui_exec` へ渡すと、**CLI と答えが変わります。**
長さを先に送る形（length-prefixed）にして、**中で CLI と同じ分け方をしてください。**

### 3. `終わる` の意味がぶつかります

いまの `終わる` は「このファイルを閉じる」です。デーモンでは
**「この接続を切る」**と**「デーモンを止める」**のどちらにも読めます。
★**接続を切るほうに割り当て、デーモンを止めるのは別の名前にしてください**
（止めるほうが危ないので、短い名前を与えない）。

## 帰属と時刻は、デーモンが押します

★**これが、デーモンにすることで新しく得られるいちばん大きいものです。**

複数の書き手が 1 つのファイルを使うなら、**「誰が・いつ」が無いと使えません。**
そして **機械が 2 つ以上あると時計も 2 つ**になり、自己申告では混ざります。
**デーモンは時計を 1 つしか持たないので、押せばずれません。**

**やり方は、いまの言葉だけで済みます**（保存の形も、ライブラリの口も変えません）。

```
受け取る: 作る (決定:ある決めごと {なぜ: "…"})
そのまま実行し、応答の JSON から名前を読む
続けて自分で 1 文 足す:
          結ぶ (決定:ある決めごと)-[書いた]->(機:名乗り {時: "2026-11-08T18:08:00+09:00"})
```

★**問い合わせの文を書き換えないこと。**応答の
`{"kind":"node","label":…,"name":…}` から名前が取れるので、文字列をいじる必要はありません。
**文を書き換える作りは必ず壊れます。**

辿れます。

```
辿る (機:名乗り)<-[書いた]-(?何)          その書き手が書いたもの
辿る (決定:ある決めごと)-[書いた]->(?機)   これは誰が書いたか
```

★**接続のときに名乗らせ、名乗らない接続は読むだけにしてください。**
代償は**書き込み 1 件につき線が 1 本 増えること**です。書き込みが少ない使い方なら問題になりません。
**取り込みのように何万件も書く使い方では、これを切れるようにしてください。**

## `詰め直す` をデーモンの中でやる

- **良くなること**: [気をつけること](../README.md#気をつけること)に書いてある
  「入れ替えの一瞬だけ錠が外れる」窓が、**デーモンの中で閉じられます**
  （外のプロセスは口の向こうに居るので、その瞬間に開きに来られません）
- **悪くなること**: ★**その 1〜2 秒、デーモンは何にも答えません**（48 MB のとき）
- **安全なこと**: ★**id を振り直してよい**のは変わりません。
  id はライブラリの外に出ないので、使う側が持っている値を壊しません

★**空いている時間に自分でやる**のは良い考えですが、
**「空いている」の判定を間違えると、誰かの問い合わせの途中で 1〜2 秒 止まります。**

## 詰まり（測ってから決めること）

| 詰まりの元 | 手 |
|---|---|
| **返りが長い** | `新しい N` が既にあります。★**デーモンが既定の上限を持ち、切ったことを `end` の行で言う** |
| **読まないクライアント** | ★**必須。**接続ごとに出力を溜めて、書ける分だけ書く。**1 つが固まると全員 止まります** |
| **`詰め直す` の 1〜2 秒** | 滅多に呼ばないので受け入れる |
| **問い合わせ自体が遅い** | ★**まだ測っていません**（下記） |
| **LAN の往復** | ★**同じ機械の中の 6〜13 倍 かかります**（上の「測った土台の性質」5）。**持続接続にしてください** |

## 持ち主の機械が落ちたとき

ファイルは 1 つの機械が持ちます。**その機械が落ちている間、他の機械は書けません。**

★**そのとき、黙って自分のところに書かせないでください。**
書かせると記憶が分かれて、あとで合わせられません（下記）。
**書けないときは、書けないと言って失敗してください。**

★ デーモンは**使う側のプロセスの子にしないこと。**
親が建て直されるたびにデーモンも消えるなら、デーモンにした意味がありません。

★ 異常終了すると、錠と口の残骸が残ります。
次に来たプロセスが「繋いでみる → 駄目なら残骸を片付けて自分が持つ」をやりますが、
**複数が同時に試すので競争します。**`O_EXCL` の錠を先に取った 1 つだけが片付ける形にしてください。

## 変えないもの

- **保存の形** — デーモンのためにファイルの形を変えない
- **ライブラリの口** — ★**埋め込んで使うのが本筋で、デーモンは選択肢です。**
  デーモンが要らない使い方（1 プロセスしか触らない）を重くしない
- **id は中だけのもの** — 外に出さないから `詰め直す` で振り直せます

★**複数の機械が別々に書いて、あとで合わせる形は採りません。**
追記しかしない形は複製に向いていますが、**id が「ファイルの中で何番目か」で決まる**ので、
別々に書くと同じ id が別のものを指します。
**採るなら id に「どこで生まれたか」を入れる＝保存の形の変更**で、
土台をまたいだバイト一致の検査もやり直しになります。
**まず「1 つが持ち、他は繋ぐ」で動かしてください。**

★ そして `詰め直す` は複製の敵です（書き直すので、送った記録と番号が合わなくなります）。
**この 2 つは同時に成り立ちません。**

## 段 0 の決着（土台をまたいで効く錠）

**デーモンが無くても効くので、ここだけ先に入れます。**使う側と相談して、次の形に決めました。

| | 決めたこと | なぜ |
|---|---|---|
| **既定** | ★**off。`yui_open` の振る舞いは変えません** | 錠を既定 on にすると「**開けないことがある**」が新しく増えます。結の都合で、使う側のアプリが起動しなくなる形は採りません |
| **口** | ★**別の関数**にします（`yui_open` に引数を足しません） | 既存の呼び出しが 1 つも変わらず、**既定 off が型で守られます** |
| **名乗り** | ★**呼び出し側から渡せます** | 機械名と pid だけでは、**同じ機械の中の CLI とアプリを区別できません** |
| **持ち主の読み方** | ★**開かずに読めます** | 使う側が「壊してよいか」を判断する材料になります |
| **壊して取る** | ★**1 回の呼び出し**で（消して作り直すまでを中でやる） | 別々の呼び出しにすると、**間に他が入れます** |
| **自動で壊すか** | ★**壊しません。判断は使う側です** | 下記 |

★**言葉（命令）の側には出しません。**言葉は開けたあとでしか打てないので、
**開けないときに外す手段になりません。**

### 自動で乗っ取らない理由

`O_EXCL` の錠は**持ち主が落ちても外れません**（`flock` は外れます）。
素朴に自動で乗っ取ろうとすると、**持ち主が生きているかを判定する必要がありますが、
土台をまたぐとできません。**

- `kill(pid, 0)` 相当が使えるのは**同じ土台の中だけ**です
- 「同じ機械か」も判定できません（loopback を共有していても hostname は別です）
- 心拍（持ち主が定期的に書き足す）は、**結に時計もスレッドも無い**ので、
  操作のたびにしか更新できません。★**開いたまま待っているだけの持ち主は「死んでいる」に見えます**

⇒ **結は「持ち主を名乗って断る」ところまでをやり、壊すかは使う側が決めます。**
使う側は自分が落ちたことを知れる立場に居ます（単一インスタンスの仕組み・前回の pid の記録）。

### 壊したあと、読み返して確かめます

消してから作り直すまでの間に、**別のところが先に作りうる**ので（この窓は無くせません）、
★**作ったあとに読み返して、自分の名乗りが入っているかを確かめます。**
入っていなければ競争に負けたので、**取れなかったものとして断ります。**

### 段 1 で入ったもの・入っていないもの

`yuid.c`（`make yuid` / `build.bat`）。テストは `tests/daemon.sh`（42 件）と、
CI の Windows の pwsh の段。話しかける道具は `tests/yuid_say.c` で、
**POSIX と Windows で同じものを使います**（`nc` はフラグが土台で違うので使いません）。

**入ったもの**

- `127.0.0.1` だけで待ち受け（LAN には出しません）
- 長さを先に送る形（`<バイト数>\n<問い合わせ>`）。**CLI と同じく 1 行ずつ実行**します
- 締めの行 `{"kind":"end","rc":N}`。`終わる` なら `"bye":true` が付いて**接続だけ**切れます
- 持続接続（1 本の接続で何度でも）
- 読むだけ（`YUI_READONLY`）。書き込む言葉は断ります
- ファイルの錠（`yui_open_locked`）。**デーモンが唯一の持ち主になります**
- 2 本 目は立ちません（口の `bind` が弾きます。土台ごとの作法は上の「測った土台の性質」4）
- `--idle 秒` で空き時間に終わります（★終わるときに錠を外します）

**★入っていないもの（段 4）**

- **返りの上限がありません。**長い返りは長いまま返ります
- **書き出しは待つ作りです。読まないクライアントが 1 つ居ると、全員 止まります**
- 同時に繋げるのは 16 本までです（超えると「いっぱいです」と断ります）

★**段 1 のデーモンを立てている間、CLI からは同じファイルを開けません**（デーモンが
錠を持っているため）。**全員がデーモンを通るか、全員が CLI を使うかの、どちらかです。**
混ぜられるようになるのは段 2 からです。
