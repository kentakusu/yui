# テスト

```
make test        Linux / macOS（ライブラリと CLI）
make test-cli    CLI だけ
build.bat test   Windows（ライブラリだけ。CLI は CI で見ています）
make test-san    AddressSanitizer / UBSan つき
make test-wasm   wasm（emscripten）。emcc と node が要ります
```

GitHub Actions で、push のたびに **Linux（gcc / clang）・macOS・Windows・wasm** の
全部で回しています（`.github/workflows/ci.yml`）。

## 中身は 2 つ

| | 見ているもの |
|---|---|
| `cases/*.txt` | 問い合わせの言葉と、その出力 |
| `test_yui.c` の後半 | 問い合わせでは作れない状況（壊れたファイル・二重オープン・開けないパス） |
| `cli.sh` | CLI だけのもの（終了コード・標準入力の読み方） |

**まだ見ていないもの**は、流すたびに `-- 見ていません:` の行で出ます。
いまは CLI の対話（端末）の道・`詰め直す` の失敗の道・wasm での排他がそれです。

★`cli.sh` は `sh` が要るので **Windows では動きません**。CI の Windows では
`.github/workflows/ci.yml` の pwsh の段が同じことを見ています。
**同じものを 2 箇所に書いているので、片方を直したらもう片方も直してください。**

## ケースの書き方

```
# コメント

> 作る (人:田中)          命令（> で始める）
(人:田中)                  出ると思う行
+ 作りました               締めの行（「N 件」など。種類まで見ます）

> 消す (田中)
! 「田中」は 2 件あり…    エラーになること（文も合わせます）

> 終わる
@                          「終わる」が返ること

== 開き直す                閉じて、同じファイルを開き直す
```

- 1 つのケースは、**毎回 空のファイルから**始まります（`yui_test_tmp.yui`）。
- 空行は区切りです。期待する行にはなりません。
- 行の中の `\r` は落とします（CRLF でチェックアウトされても動きます）。
- `repack.txt` と `repack_empty.txt` は、出力に**ファイルのバイト数**が入ります。土台をまたいで
  同じバイトになることは CI で見ているので、どの土台でも同じ数になります
  （数が変わったら、保存の形が変わったということです）。

## 期待を作り直す

```
make record        ケース全部を書き直す
./build/yui_test --record tests/cases/basic.txt   1 本だけ見る
```

★**出てきたものを目で見てから commit してください。**
見ないで入れると「いま そうなっている」を固めるだけで、テストの意味がなくなります。
`make record` で差分が出たときは、**実装が変わったのか、壊れたのか**を先に決めてください。

## ファイル名が ASCII な理由

ケースのファイル名だけ ASCII です（中身は日本語です）。
Windows の `cmd` はコマンドライン引数を cp932 で渡すので、日本語のファイル名を
付けると、テストが失敗したときに出るパスが化けて開けなくなります。
関数名が ASCII なのと同じ理由です。
（CLI の `yui.exe` は引数を UTF-16 から取り直しますが、テストの実行ファイルは
それをしていません。ASCII の名前で足りているので、置いていません。）

## 索引の自己検査

テストのビルドには `-DYUI_SELFCHECK` が付きます。
`探す` を実行するたびに、**索引を使った答えと全件走査の答えを突き合わせ**、
違っていたらその場で止まります。索引の取りこぼしは「結果が少ない」形で出るので、
答えだけ見ても気づけません。
