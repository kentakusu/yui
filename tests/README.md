# テスト

```
make test        Linux / macOS（ライブラリと CLI）
make test-cli    CLI だけ
build.bat test   Windows（ライブラリだけ。CLI は CI で見ています）
make test-san    AddressSanitizer / UBSan つき
make test-wasm   wasm（emscripten）。emcc と node が要ります
```

GitHub Actions で、push のたびに **Linux（gcc / clang）・macOS・Windows・wasm** の
全部で回しています（`.github/workflows/ci.yml`）。

## 中身は 2 つ

| | 見ているもの |
|---|---|
| `cases/*.txt` | 問い合わせの言葉と、その出力 |
| `test_yui.c` の後半 | 問い合わせでは作れない状況（壊れたファイル・二重オープン・開けないパス・錠） |
| `cli.sh` | CLI だけのもの（終了コード・標準入力の読み方） |

**まだ見ていないもの**は、流すたびに `-- 見ていません:` の行で出ます。
いまは Windows の CLI の一部と、`詰め直す` が書いている途中で失敗する道です。
wasm ではもう 1 行 増えます（`yui_open` の二重オープン。`flock` が何もしないため）。

## 土台をまたいで効く錠（`yui_open_locked`）

★**ここで見ているのは「錠の決まりどおりに動くか」だけです。土台をまたいで本当に
排除できるかは、1 つのプロセスからは確かめられません**（別の土台のプロセスを
起こす必要があります）。その実測は `docs/デーモンの構想.md` の
「測った土台の性質」にあり、**そこが正**です。ここの検査は代わりになりません。

★**「壊して取ったあと読み返して確かめる」だけは、本体に差し込み口を置いて見ています**
（`yui_selfcheck_took_lock`。`-DYUI_SELFCHECK` のときだけ在ります）。
取り合いの窓は 1 プロセスからは作れないので、**これが無いとその確かめは
どの検査にも守られません**（実際、入れる前に外して流しても 1 件も落ちませんでした）。

### この検査に検出力があることの確かめ方

わざと壊して、落ちることを見てください。**落ちなければ、その検査は何も守っていません。**
下の 10 とおりは、入れたときに 1 つずつ当てて、狙った検査名で落ちることを見ています。

| 壊し方 | 落ちるべき検査 |
|---|---|
| `yui_close` で錠を消さない | 閉じると錠が消えること |
| 断られた側が持ち主の錠を消す | 断られた側が閉じても錠が残ること |
| 名乗りの制御文字を掃除しない | 名乗りの改行が空白になること |
| `LOCK_SUFFIX` を変える | 錠を使って開くと 錠のファイルができること |
| 錠を `flock` より**後**に当てる | 断る理由が錠のことであること |
| 旗が無くても勝手に壊して取る | 残骸があると断ること |
| 壊して取ったあと読み返さない | 取り合いに負けたら断ること |
| 印の材料を `time()` だけに戻す | 錠の印が毎回 変わること |
| 読むだけの関所を外す | 読むだけなら断ること: …（4 件） |
| 表で `消す` を「書かない」扱いにする | 読むだけなら断ること: 消す (人:田中) |

★**下 3 つは、同じ壊し方でも落ちる検査が違います。**関所そのものを外すと 4 件 落ち、
表の 1 行だけを間違えると**その言葉の 1 件しか落ちません**。
⇒ **言葉を足すときは `writes` の列を書き忘れても、読むだけの検査がその言葉だけ落ちます。**

★**5 行目が一番 大事です。**錠を `flock` より後に当てると、同じ土台どうしの衝突は
`flock` が先に弾くので、**「持ち主を名乗る」が働かないまま検査は通ります。**
手前のガードが先に弾く形なので、対照を取らないと気づけません。

★`cli.sh` は端末として開いたときの道も見ます（呼び出しの合図を出す・行番号を
出さない）。`isatty(0)` が真でないと通らないので、**GNU の `script` で疑似端末を
割り当てて**測っています。

★**BSD（macOS）の `script` では測れません。**疑似端末は作れますが、パイプで
渡した入力が確実に渡りません（CI の macOS で実測。合図と起動の 1 行は出るのに、
命令の結果が出ない）。**無理に通すより「見ていません」と出すほうが正確**なので、
その節だけ飛ばします。

`詰め直す` の失敗の道は、**本物の失敗で起こして**見ています。どこで見ているかが
土台で違うので、置き場を分けてあります。

| 失敗する段 | どこで見ているか | 起こし方 |
|---|---|---|
| 作業用のファイルを作れない | `cli.sh`（POSIX のみ） | 置き場を読み取り専用にする |
| 作業用のファイルが既にある | `test_yui.c` | 自分で置く |
| 入れ替えられない | CI の Windows（pwsh） | 行き先を他のプロセスが削除を許さない形で掴む |
| 書いている途中で失敗する | **見ていません** | 置き場を尽きさせる手が portable に無い |

★**POSIX では「入れ替えられない」を起こせません。**置き場を書けなくすると、
作業用のファイルを作る段で先に止まるためです。逆に Windows では
「掴んだまま置き換えられない」が作れます。**土台ごとに起こせる失敗が違う**ので、
片方だけ見て「通した」と書かないようにしています。

★`cli.sh` は `sh` が要るので **Windows では動きません**。CI の Windows では
`.github/workflows/ci.yml` の pwsh の段が同じことを見ています。
**同じものを 2 箇所に書いているので、片方を直したらもう片方も直してください。**

## ケースの書き方

```
# コメント

> 作る (人:田中)          命令（> で始める）
(人:田中)                  出ると思う行
+ 作りました               締めの行（「N 件」など。種類まで見ます）

> 消す (田中)
! 「田中」は 2 件あり…    エラーになること（文も合わせます）

> 終わる
@                          「終わる」が返ること

== 開き直す                閉じて、同じファイルを開き直す
```

- 1 つのケースは、**毎回 空のファイルから**始まります（`yui_test_tmp.yui`）。
- 空行は区切りです。期待する行にはなりません。
- 行の中の `\r` は落とします（CRLF でチェックアウトされても動きます）。
- `repack.txt` と `repack_empty.txt` は、出力に**ファイルのバイト数**が入ります。土台をまたいで
  同じバイトになることは CI で見ているので、どの土台でも同じ数になります
  （数が変わったら、保存の形が変わったということです）。

## 期待を作り直す

```
make record        ケース全部を書き直す
./build/yui_test --record tests/cases/basic.txt   1 本だけ見る
```

★**出てきたものを目で見てから commit してください。**
見ないで入れると「いま そうなっている」を固めるだけで、テストの意味がなくなります。
`make record` で差分が出たときは、**実装が変わったのか、壊れたのか**を先に決めてください。

## ファイル名が ASCII な理由

ケースのファイル名だけ ASCII です（中身は日本語です）。
Windows の `cmd` はコマンドライン引数を cp932 で渡すので、日本語のファイル名を
付けると、テストが失敗したときに出るパスが化けて開けなくなります。
関数名が ASCII なのと同じ理由です。
（CLI の `yui.exe` は引数を UTF-16 から取り直しますが、テストの実行ファイルは
それをしていません。ASCII の名前で足りているので、置いていません。）

## 索引の自己検査

テストのビルドには `-DYUI_SELFCHECK` が付きます。
`探す` を実行するたびに、**索引を使った答えと全件走査の答えを突き合わせ**、
違っていたらその場で止まります。索引の取りこぼしは「結果が少ない」形で出るので、
答えだけ見ても気づけません。
