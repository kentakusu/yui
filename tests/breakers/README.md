# 陽性対照（わざと壊して、検査が落ちるか見る）

**「テストが在る」と「そのテストが守っている」は別です。**
ここの道具は、実装をわざと壊して、**狙った検査名で落ちること**を確かめます。
**落ちなければ、その検査は何も守っていません。**

```sh
python3 tests/breakers/lib.py      # ライブラリ（yui.c）— 錠・読むだけ・印
python3 tests/breakers/cli.py      # CLI（yui_cli.c）— --read / --wait / 旗
python3 tests/breakers/daemon.py   # デーモン（yuid.c）— やりとり・錠・空き時間
```

全部 通ると「ぜんぶの壊し方で落ちました」と出ます。

## ★ 使う前に知っておくこと

- ★**ソースを書き換えます。**終わると md5 で突き合わせて元に戻しますが、
  **作業中の変更がある状態では走らせないでください**（戻すときに消えます）。
  走らせる前に `git status` を見てください
- ★**CI では走らせません。**`make test` にも入れていません。ソースを書き換える
  道具を自動で回すと、落ちた拍子に壊れたまま残ります
- `python3` が要ります（`make test` には要りません）

## ★ ここは実装と一緒に古くなります

壊し方は**ソースの文字列に当てて**います。実装を書き換えると、
**当てる場所が見つからなくなります**（「当てる場所が 0 件」と出ます）。

★**そのときは、黙って飛ばさずに直してください。**飛ばすと、
その壊れ方を見ている検査が在るのかどうかが分からなくなります。
**実際に 1 度 起きました**——`open_body` に引数を足したときに、
「錠を `flock` より後に当てる」の当てる場所が消えました。

## これで実際に見つかったもの

★**どれも、ふつうにテストを流しているだけでは分かりませんでした。**

| 見つかったこと | どう分かったか |
|---|---|
| 「壊して取ったあと読み返して確かめる」を**どの検査も守っていなかった** | 外しても 1 件も落ちなかった。1 プロセスからは取り合いを起こせないため。本体に試験用の差し込み口を置いて守らせた |
| 「CLI は `<パス>.錠` を作らない」の検査が**無力だった** | 閉じたあとに見ていたので、正常終了で外れた姿を見るだけだった。**開いている最中**に見るよう直した |
| 錠を `flock` より**後**に当てると、同じ土台どうしでは「持ち主を名乗る」が働かない | 手前のガードが先に弾く形。対照を取るまで気づけなかった |

落ちるべき検査の一覧は `tests/README.md` にあります。
